# codegarden — UI prototype

A Miro-like infinite whiteboard that shows a repository as a garden. Two sample repos are included:
`../blakkis` (Node.js Telegram bot) and `../nitter` (Nim web app). Switch between them with the
picker next to the logo, or with `?repo=nitter`.
Zoom changes **what** you see, not just how big it is:

| Level | Camera scale | What you see |
|---|---|---|
| 1 · Architecture | < ~0.2 | Program-flow stages (or files/dirs, toggle) with aggregated arrows; functions appear as plant silhouettes |
| 2 · API contracts | ~0.36 – 0.95 | Function cards (name, params, kind, file:line) and call arrows; code appears as a token silhouette |
| 3 · Code | > ~1.5 | Real source with highlighting; arrows leave from the exact call-site line and enter the callee's header |

The levels crossfade continuously (`src/zoom.js`), and everything sits in one nested world geometry
(group ⊃ card = code pane), so zooming toward the cursor never jumps.

## Run

No Node is needed. The page uses buildless ES modules, and PixiJS v8 loads from jsDelivr.

```sh
./serve.sh            # serves ../ (codegarden) on http://localhost:8137/garden/
```

## Controls

- **Ctrl + wheel** / trackpad pinch: zoom at cursor (browser zoom is blocked)
- **wheel / drag**: pan · **double-click**: fly to card / group · **click**: pin highlight · **Esc**: clear
- **T**: toggle Program flow ↔ File structure (cards fly between layouts) · **F**: fit · **1/2/3**: jump to level
- **Click an underlined name in code** (level 3): fly to that function's code · **Backspace** / Alt+← / **← Back**: return

## Data

- `data/blakkis.json` is generated from a hand-curated spec in `tools/gen_data.py` (functions, flow groups and calls).
  The script only resolves line ranges, call-site lines and the clickable spans from the real sources.
- `data/nitter.json` is generated by `tools/gen_nitter.py`. The architecture is curated by hand: flow groups,
  the file → group mapping, external services (Browser, X API, Redis) and how code connects to them.
  Top-level procs/templates, Jester route handlers, imports and call sites are extracted from the Nim sources.
  Names are resolved like this: same file, then imported modules, then transitive imports, then a unique global
  match. Locals and object fields are filtered out. Overloads are linked to every candidate in the winning tier.

```sh
python3 tools/gen_data.py && python3 tools/gen_nitter.py
```

To add another repo, put it next to `garden/`, write a generator that emits the same JSON shape
(`repo, title, lang, root, groups, dirs, functions, calls, links, requires`), and add it to the picker in `index.html`.

## Layout of the code

- `src/main.js`: bootstrap, input, frame loop
- `src/camera.js`: smoothed cursor-anchored zoom, fly-to
- `src/zoom.js`: level weights from the camera scale
- `src/layout.js`: flow columns and file/directory masonry
- `src/scene/groups.js`: beds and morphing labels
- `src/scene/cards.js`: L2 cards ↔ L3 panes
- `src/scene/code.js`: code rasteriser and silhouettes
- `src/scene/edges.js`: screen-space edges
- `src/scene/grid.js`: dot grid

## Headless screenshots

`?shot=6000` holds the load event and steps the frame loop by hand, which is useful with
`firefox --headless --screenshot`. Other parameters: `repo=…`, `mode=files`, `focus=<function id>`, `s=<scale>`,
`hover=<function id>`, `jump=<function id>` (simulates clicking a link).
